# Feishu webhook channel

Unified external bundle for official Harness 0.2.1-rc.5. Install core first, then this tarball. Channel and business features ship together; the former separate feishu-tools bundle is retired. Its row starts enabled on a profile providing the official webServer/tools/Agent/Session/credentials services. Missing configuration enters local setup mode instead of terminating the host or admitting unauthenticated webhook work.

Includes authenticated text/post input, administrator and optional chat admission checks, durable inbox/outbox, chat/thread mapping, serialization, recovery and owned callbacks; native controls, progress/batching, approval/question answerers, 24-hour attachments, artifact hashing and official plain reminders. The integrated business module provides application-only Bitable five-operation tools, documents/wiki/Drive/Sheets, calendars and tasks. Set businessEnabled=false to retain only the channel; disable the whole bundle to unload both. Native compact is offered only when mounted. Codex/adviser remain separate; KB/full automation are later phases.

On first load, or when values are missing, open Harness Settings → Telebot 插件 → 飞书配置. This is a native client settings section, not a standalone webpage or iframe, and uses the official owner connection. Config remains under DSH_HOME/plugins/telebot-feishu/config/: config.json, config.example.json and README.txt. Obsolete endpoint.json/setup.token are removed on upgrade without changing credentials or business data. Non-secret fields and resource metadata go to the atomic config file; secret values go only through official credentials, leaving refs in JSON. All settings are entered manually; Base tables can be discovered from an explicitly supplied link. Every business operation uses FEISHU_APP_TENANT and the configured application credentials. OAuth, user tokens, scope editing and env-import UI/API are removed.

The setup page requires its local capability, exact Host/Origin and a loopback socket; proxy requests are denied. Bootstrap, saves and runtime changes are serialized; queued/running work and pending delivery block reconfiguration. New admission pauses during a change and the worker starts only after config commits. Failure restores the previous runtime, stale revisions are refused, and restart rotates setup access. File config is authoritative after first save. See [configuration](../../docs/feishu-configuration.md) and [current status](../../docs/status.md).

`/cd` accepts an existing absolute directory within the configured workspace, checking canonical paths and junctions. Busy or queued conversations cannot switch. The old native session is retained; the new mapping commits only after session preparation. `/model provider/model` changes the current conversation and persists its selection. Status shows the actual model and cwd where available. Interrupted mutating commands become unknown and are never automatically replayed.

Set appId, adminUserIds and an absolute workspace. Secrets default to FEISHU_APP_SECRET, FEISHU_VERIFICATION_TOKEN and FEISHU_ENCRYPT_KEY refs. At least a verification token or signed/encrypted key is required. Missing admins grant nobody access. The optional allowedChatIds field restricts production chat admission. The official web server owns the webhook listener; configuration is registered with the core native settings service on the root owner connection.

The default database is under the official DSH_HOME, namespaced by app ID, not the source tree. It records separate input, execution and delivery outcomes. Uncertain execution or send outcomes are not blindly retried. Confirmed rate-limit rejection retries the same outbox UUID; the platform's UUID window does not imply permanent exactly-once delivery. Back up the database with SQLite backup or stop the owning profile before copying it.

Multiple workers on the same database are rejected by a renewable lease. A crash may require waiting for that lease to expire. Stopping the plugin unregisters its route, cancels/drains its owned Agent work and releases the database lease; uninstalling preserves data.
