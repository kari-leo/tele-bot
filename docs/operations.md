# 使用与维护

配置入口和目录见[安装](installation.md)。业务取决于已启用插件、实际账户权限和当前模型的工具目录。

## 对话与确认

优先直接描述任务，例如“只检查这个项目”“把这三条记录的截止日期改到下周五”“明天下午三点提醒我”。结果使用富文本或卡片，不把内部 JSON 当聊天回执。

原生桌面所有者默认完整权限，inspect/plan 始终只读。飞书仍检查管理员与资源白名单。多维表格记录的新增、修改直接执行并核验（单条和多条一致）；删除及其他业务需要确认时先给冻结预览；可用自然语言同意或拒绝，例如“好的，请修改吧”“好的，请修改把”“可以，就按你说的做”或“这次先别改了”。当前会话模型结合对话历史、工具结果与冻结预览识别口语和错别字；支持“这些全部确认”“第一项和第二项都同意”等批量确认。可以在确认中附带新问题或其他要求，确认后将剩余原文及实际结果交回官方对话队列；解析失败、歧义也保留原消息继续解释。要求改变同一预览内容则进入对话重做预览。批量逐项重检有效性并给出富文本卡片回执；命令只作备用，不要求固定两个字或单独发送命令。业务预览 15 分钟有效，过期需重新生成。

提问卡片可直接选项回答，自由回答用“回答：内容”，多问题用“回答1：内容”。审批和业务确认并存时必须明确选择。提问 5 分钟过期、重启失效，无默认授权；未回答卡片不阻塞新消息，旧答案回原请求，完成结果进入后续上下文。

进度在同一条 Markdown 消息中更新并最终覆盖。webhook 已接收不等于执行或发送成功；执行、上传和投递有独立回执。

表格按目标名称筛选并只查询所需字段；模型工具默认每页 20 条，返回不完整标记及后续游标时需要继续分页，不能把当前页当全表。旧的五个 bitable_* 工具别名从模型目录移除，使用 feishu_bitable_*；聊天命令不变。定时任务和表格工具提供结构化参数，旧 JSON 参数仍兼容但不能混用。参数错误须按返回说明修正，不通过 Shell 或内部数据库绕过业务接口。

## 常用控制

| 命令 | 用途 |
|---|---|
| /help、/status | 当前能力、模型、目录、运行/排队/未知状态 |
| /stop | 停止当前执行，保留排队消息，不撤销已发生的操作 |
| /model、/model provider/model | 查看或切换当前会话模型，不改其他会话 |
| /cd、/cd 绝对路径 | 查看或切目录；飞书限配置 workspace 内真实路径，忙碌时拒绝切换 |
| /new、/reset | 在当前目录新建会话，保留历史和业务数据 |
| /compact | 调用官方上下文压缩；会话须空闲，无参数，摘要可能使用当前模型 |
| /permission、/setting | 查看会话权限和设置，全局设置在官方页面修改 |
| /send 绝对路径 | 发送当前工作区内通过校验的文件 |
| /bitable list、/bases list | 查看已登记表格和 Base；也可自然语言增删 Base 链接 |
| `/codex history [关键词]`、`/codex history --archived [关键词]` | 飞书本人私聊打开历史卡片，点击查看详情、翻页或刷新。也可用 `/codex history <序号>`、`/codex history --next`、`/codex read <会话ID>` 或 `/codex read --next`。 |
| 「继续此会话」按钮、`/codex resume <序号或会话ID> <任务>` | 点按钮后，在 10 分钟内直接发送一条文字任务或回复任务卡片，在原会话的允许工作区继续一轮。可以发「取消」退出，或用 `/new` 另开会话。未点继续时，新普通对话会使旧卡片失效。 |
| /schedule list、get、history、status | 查询任务、执行及投递记录 |

已知控制命令直接分流，未知斜杠命令返回帮助。切目录创建新会话、不继承旧确认；既有任务仍用创建时冻结的目录和模型。

## 会话长度与恢复

会话没有累计使用 token 后永久失效的配额；每次模型请求受该模型的上下文窗口限制。输入、工具定义、历史和输出预留共同占用窗口，不能把请求的 maxTokens 当作上下文容量。

当前官方 0.2.2-rc.3 的默认预设包含自动压缩及 /compact。自动压缩在步骤之间检查请求压力，旧历史转为摘要并保留近期内容；原始会话日志保留，摘要仍可能遗漏细节。默认阈值同时受窗口比例、输出预留和压缩余量约束，并非一律到 80% 才触发。模型返回可识别的上下文溢出时，默认最多尝试一次压缩恢复；配置、摘要模型或请求仍过大都可能使恢复失败。

飞书使用同一官方 Agent，插件不自行清空或轮换会话。压缩失败后本轮可能返回“本轮未完成，请检查宿主模型或工具状态”，不代表聊天或业务数据被删除。等待空闲后单独发送 /compact；仍在运行则先 /stop。持续失败时发送 /new 或 /reset，在原工作目录和当前模型下新建会话，再补充任务摘要；旧历史与业务数据保留，但新会话不自动继承旧对话和确认授权。先检查已发生的外部操作，避免重复提交。

响应配置示例见 [responsive-model.patch.example.yml](../examples/responsive-model.patch.example.yml)：官方 account provider 的流空闲超时设为 60 秒、最多重试两次，默认低思考强度，deepseek-flash 每次输出上限为 16,384 token。这不是上下文窗口或整个任务的总时限；持续收到数据仍可继续，显式会话模型设置可能覆盖默认值。无需修改官方 Harness。长历史仍需通过官方 /compact 或 /new 处理，插件不会删除历史来减小请求。

## 业务规则

- **Codex**：inspect/plan 强制只读，飞书 apply 先确认。明确的飞书续聊命令仅授权绑定消息、原会话、原目录及任务的一轮执行。同一消息去重。归档线程只读，续聊显式启用工作区写沙箱并关闭 Shell 网络。执行上限 20 分钟，Skill 使用冻结运行副本，产物另核验大小与哈希。
- **报告/发布**：报告只新建；发布保持原文正文；Git 单独冻结并授权指定文件、HEAD、分支和远端。覆盖、移动、隔离删除先预览并保留恢复副本，unknown 不重推。
- **自动化**：remind 只提醒；飞书 auto 创建/修改后另需本人执行预授权，confirm 到点逐次确认。原生完整权限可内部授权 auto，显式 confirm 仍按次确认。任务独立执行，修改撤销旧授权。
- **恢复与范围**：skip/run_once/ask 决定迟到处理，weekday 为周一=0，首次时间带时区。授权用户默认可用任意实际存在目录，显式受限原生入口仍受限。stop 只停本次执行，retry-delivery 只恢复待投递或明确失败项。
- **顾问/知识库**：顾问是可选无状态第二意见，不可用时主任务可继续。知识库由上游管理，附件不自动入库。

附件可先发后描述要求，或引用本人同 chat/thread 的附件，暂存 24 小时。文档/出站上限 30 MiB、正文 120,000 字符；图片单张 20 MiB、最多 8 张且合计 30 MiB，受实际 provider 限制。文件校验真实路径、归属、大小及哈希；投递失败不重做业务。

## 备份与恢复

更新/迁移前确认没有运行任务并退出 profile，一起备份 profile 配置、官方 credentials、plugins、sessions、storages 和附件。知识库包括元数据、chunks SQLite、raw 原文及模型配置。依赖/缓存不代替业务数据。

SQLite 使用 backup API，或停机后一并复制主文件及相关 WAL，不能只复制运行中的主 sqlite。备份含凭据，只放在受保护的本机位置，不提交或写入报告。

恢复保持单写者，核对版本、数量、权限和 unknown 后再恢复入口。强制终止后，须等旧渠道租约自然到期再启动，不删除租约来绕过单写者保护。卸载保留数据；代码回退不代表支持数据降级。渠道当前 schema 3，旧代码须配套兼容快照，恢复会舍弃快照后的记录。

## 排障

| 现象 | 处理 |
|---|---|
| 未就绪 | 检查启用状态、设置缺项、精确宿主版本和加载日志 |
| 飞书 403 | 核对来源校验、应用、管理员和卡片归属，不打印凭据/原始事件 |
| 400 / 413 | 检查格式和大小限制 |
| 503 | 检查队列、存储、worker 和并发实例；已接收事件仍去重 |
| 数据库被占用 | 停止另一实例或等崩溃租约过期，不删除数据库绕过 |
| unknown / 丢回执 | 先查会话、业务状态和远端实际结果，不盲目重发、重推或重建 |
| read_timeout / read_dns / read_connection | 读取超时或连接失败；可安全重试的读取最多两次，包含只读 POST 查询，不自动重试写入 |
| read_tls / read_permission / read_invalid_response | 核对证书、系统访问权限或响应格式；不盲目重试，诊断只保留分类及安全传输错误码，不回显响应体/凭据 |
| 模型结束但没有最终答复 | 按失败反馈，先查询工具是否已完成操作；不会把工具调用前的进度文字当成功结果，也不重做本轮业务 |
| Windows Git file 传输失败 | 可能受官方沙箱 MSYS 管道限制，保留提交状态，不关闭沙箱重推 |

正式启动日志在本机 runtime 的 logs，业务状态在 DSH_HOME。旧日志端口可能过期；从当前官方入口诊断，不公开所有者 URL/token。真实检查见[测试入口](../tests/README.md)，历史发送许可不自动延续。
