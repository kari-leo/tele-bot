# 统一飞书插件、配置 UI 与真实联调记录

更新：2026-10-30。以 [总开发计划](../../../HARNESS_DEVELOPMENT_PLAN.md) 和当前工作树为准，尚未提交 Git。本轮用户要求合并 feishu/feishu-tools、提供文件配置和首次使用 UI，并沿用旧项目测试范围；随后明确批准了专用群中的三条测试发送。

## 已交付

- 当前生产安装集是 core、feishu、codex、adviser 四包；渠道、OAuth 和四类飞书业务均编入同一个 feishu。原 feishu-tools 源码已移入 `plugins/feishu/src/business/`，不再生成该独立 tarball 或 patch row。
- 首次/缺项配置模式、原子配置文件、官方 credentials 引用、本机配置 UI、旧 env 字面导入、Base 链接发现、资源选择和测试 chat 白名单。
- 保存与启动串行，处理排队/执行/待投递保护，切换期停止准入，配置提交后启用 worker，错误回滚及重启保留；配置页面经过真实浏览器保存和文件核对。
- 真实 Base 与专用群测试工具均显式 opt-in。消息发送记录固定 UUID 和自己的消息 ID，已成功类型再次运行只回读；未知发送结果必须先对账，不自动再发。

## 验证

最新计数和可重跑证据见 [兼容记录](../../compatibility.md) 与 `tracking_outputs/2026-10-30-feishu-unified-final.json`。命令和运行边界见 [testing.md](../../testing.md)。本地/宿主验收始终只使用 loopback 模型；没有调用付费模型。

指定 Base 的真实 API 检查通过 9 项：结构/字段、冻结新增、重复确认不再写入、定向查询、更新回读、清空字段、补充期限与用户绑定、冲突拒绝/取消、确认删除。只写了本轮独立标记记录，未改表结构/旧记录，测试记录全部清理。未以大批量造数或真实 429 压测冒充分页/故障测试。

在用户解除暂缓并明确批准三项发送后，专用群通过 3 项：生产富文本发送及本消息回读、无执行按钮的卡片发送及回读、约 50 字节文件上传/发送/本消息下载并核对 SHA-256。总计只发送这三条，作为可见测试证据保留；未读取其他聊天历史。

群资料 GET 返回飞书错误 `99991672`，缺少 `im:chat:readonly` / `im:chat` / `im:chat:read` 列表中的适用权限；该项单独保持待验收，未扩大权限。三项发送与自己消息回读已经按实际接口完成，不能将“群信息查询未授权”误写为“发送失败”。

公网 `https://feishu.windborne.cc/feishu/webhook` 的 GET 可达性检查返回 502。没有改动公网回调或切换旧服务，也未据此验收真实平台的入站消息、按钮、提问审批或 OAuth。
